# Four-Choice Illustration Checkpoint

Use this checkpoint after analyzing an existing presentation and selecting the scenes that would benefit from illustration. The conversation is the selection interface.

## Lock the deck language first

Before generating previews:

- use the presentation's existing visual language;
- select four or fewer colors from the deck, including background and primary ink;
- preserve the deck's typography, shape language, and tone;
- choose one real, representative scene from the intervention plan;
- keep facts, wording, and information density consistent across all four previews.

This checkpoint chooses the illustration direction. It never asks the user to choose a new palette or presentation template.

## Core contract

- Present exactly four options.
- Use a 4:3 canvas for each preview.
- Arrange A and B on the first row and C and D on the second.
- Give every preview the same width, height, and visual weight.
- Size the grid for direct reading in the conversation. On desktop, each preview should occupy close to half of the available wide agent surface and normally render at least 420 CSS pixels wide.
- Preserve enough detail for the user to recognize composition, illustration treatment, and hierarchy without clicking, opening, or zooming.
- Place only the plain black letter `A`, `B`, `C`, or `D` directly beneath each preview.
- Use a neutral white or off-white label area. Keep deck colors inside the illustrations.
- Keep names, descriptions, titles, colored badges, icons, arrows, recommendation markers, and explanatory copy outside the selector.
- Maintain clear gutters and independent boundaries so the four options cannot read as one continuous comic or process.
- End with the localized equivalent of: `Reply A, B, C, or D to continue.`

Use a native four-card selector when available. Use the host's wider inline comparison surface whenever ordinary chat width would reduce the options to thumbnails. Otherwise use a large 2×2 contact sheet with minimal outer margins. On narrow screens, preserve A, B, C, D reading order and stack only when required for readability.

## Compare one variable

Keep the deck palette, typography, story scene, facts, and canvas dimensions fixed. Change one meaningful illustration dimension, such as:

- group scene versus focused human interaction;
- environmental scene versus evidence-board composition;
- editorial comic versus restrained geometric system;
- linear sequence versus ecosystem or feedback-loop composition.

Do not combine unrelated palette, typography, content, and layout changes in one choice set. The user should immediately understand what A–D changes.

## Use real project content

Use the actual project name, roles, artifacts, setting, and verified evidence from the supplied deck. Never invent companies, quotes, salaries, metrics, participant details, outcomes, or personal history. When data is unavailable, use neutral field labels, gray lines, dots, or abstract marks.

## Advance from one letter

After the user replies with A, B, C, or D:

1. Confirm the selected direction in one sentence.
2. Apply it to every approved infographic scene.
3. Adapt final illustration dimensions to each target slide.
4. Preserve the surrounding deck's visual system and all unaffected slides.
5. Continue without asking the user to confirm the same choice again.

If the user asks for another set, generate four new options and reuse A–D. If the user combines directions, such as `A + C`, summarize the combination in one sentence and continue unless the request is genuinely ambiguous.
